# Known legacy quirks: settlement slice

Behaviour the Struts application has, that a fresh rewrite would not, and
that the settlement service reproduces on purpose (ADR-001, decision 7). Each
entry says where the behaviour lives, how it was found, and what keeps it in
the service. Nothing here is a defect report; it is a list of things we
promised to keep the same until a change record (`docs/changes/CHG-nnn-*.md`)
says otherwise.

| Id | Quirk | Legacy location | How found | Kept in service by | Rule |
| --- | --- | --- | --- | --- | --- |
| QUIRK-01 | Rounding is `Math.round(amount * 100.0) / 100.0` on a `double`. `1.005` settles at `1.00`, because `1.005 * 100.0` is `100.49999999999999`. `BigDecimal` with `HALF_UP` gives `1.01`. | `service/SettlementCalculator.calculate` | `transcripts/settlement_half_cent.json`; `SettlementCharacterizationTest.settlementHalfCentRoundsDownButDisplaysCoveredUp` | `domain/SettlementCalculator` runs the same `double` statements; `SettlementCalculatorTest.halfCentRoundsDownButDisplaysCoveredUp` | SETTLE-R09 v2 |
| QUIRK-02 | Money display is `String.format("%.2f", double)`, which rounds the decimal representation half up. The same screen shows `coveredAmount 1.01` next to `settlementAmount 1.00` for input `1.005`. | `web/tag/FieldTag.formatValue` | reading `FieldTag` after QUIRK-01 | `domain/LegacyDisplay.money` uses the same format call | SETTLE-R10 |
| QUIRK-03 | When the claim or its policy does not exist, calculate uses a policy limit of `10000` and still answers. | `SettlementCalculateAction`, `double limit = 10000;` | reading the action; confirmed with `claimId=9999` (`docs/analysis/settlement-slice.md`) | `SettlementService.FALLBACK_LIMIT`; `SettlementControllerTest.unknownClaimUsesFallbackLimit` | SETTLE-R05 v2, OQ-01 |
| QUIRK-04 | Save has no such fallback: a missing claim dereferences `null` and lands on the system error screen. | `SettlementSaveAction` | reading the action while porting save | `SettlementService.save` throws `ClaimNotFoundException` | SETTLE-R12 |
| QUIRK-05 | Any exception ends on `error.jsp` with HTTP 200 and no `ns:error` marker, so the transcript shows `result: forward:/WEB-INF/jsp/error.jsp`, `status 200` and an empty `validation_errors` list. | `struts-config.xml` `<global-exceptions>`, `error.jsp` | `transcripts/settlement_bad_deductible.json`; pull request review noticed the first service draft added `errors.system` to the list | `api/LegacyErrorHandler` returns screen `error`, status 200, no fields, no errors | SETTLE-R06 |
| QUIRK-06 | Missing or non-numeric `claimId`, `coveredAmount` and `depreciation` silently become `119`, `5000` and `0`. | `ClaimsActionSupport.integer` and `.decimal` | reading the action | `domain/LegacyCoercions.integer` and `.decimal` | SETTLE-R02, SETTLE-R03 v2 |
| QUIRK-07 | `calculated_date` on save is the constant `2019-04-01`, and `calculated_by` is the session user. | `SettlementSaveAction` | reading the action | `SettlementService.SAVE_DATE`; operator is the `northstar.operator` property | SETTLE-R12 |
| QUIRK-08 | Amounts are parsed with `Double.parseDouble` and the arithmetic runs on `double` end to end. Every spelling `Double.parseDouble` accepts is a valid amount: `1d`, `0x1.0p0`, `Infinity`, `NaN`, and values with surrounding whitespace; `1,000` is not. A covered amount of `Infinity` is capped at the policy limit; `NaN` fails both the floor and the cap comparison and `Math.round(NaN)` is `0`, so it settles at `0.00` while the screen shows `coveredAmount NaN`. There is no length limit on the input (OQ-05). A first service draft parsed with `BigDecimal`, which rejects all of these and rounds differently (QUIRK-01). | `ClaimsActionSupport.decimal`, `SettlementCalculator.calculate` (`Double.parseDouble(deductible)`) | pull request review of the service against the legacy source | `domain/LegacyCoercions` (`Double.parseDouble`), `double` fields on `SettlementResult` and `SettlementRow`; `LegacyCoercionsTest.acceptsEverySpellingDoubleParseDoubleAccepts`, `SettlementCalculatorTest.arithmeticIsDoubleArithmetic` | SETTLE-R03 v2, SETTLE-R04, SETTLE-R06, SETTLE-R09 v2 |
