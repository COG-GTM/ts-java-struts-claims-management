Payment slice: how it actually behaves

NorthStar claims monolith, /payment/*.do. Built from the legacy source, the two payment transcripts and 29 live requests against the running app. Source of truth: docs/analysis/payments-slice.md.

Summary

  • Issuing a payment is one unguarded request: any signed-in GET or POST to /payment/issue.do writes an ISSUED check, with no form, approval, review, claim-status check or amount bound (findings 5, 7, 21, 22, 27, 31).
  • Missing or bad input is replaced silently: claim → 119, amount → the newest settlement's amount (0.00 on a fresh seed), check number → CHK-<id> whatever was sent (findings 9, 18, 19, 25, 26).
  • Missing payee, method or settlement, and concurrent issues, end on an error page that answers HTTP 200 (findings 14, 17, 33, 52).
  • The read screens default to claim 119 and payment 61; the history "Payment detail" link is hard-coded to payment 61 (findings 35, 37, 38, 39).
  • Of 26 documented statements about the slice, 13 are contradicted by the code or the live run, 12 are confirmed and 1 cannot be checked here (section 8).
  • The two payment transcripts show none of this: they send one valid POST and read "db_state" by scraping a screen (findings 57, 58). Precondition for every live step: a fresh make seed (60 seeded payments, ids 1–60; seeded settlement 119 has amount 0), then make run. Payment ids are max+1, so the ids quoted below only hold for that starting state.

Screens

  • — no screen posts to issue.do; → PaymentIssueAction (GET or POST)
  • — confirmation, 3 fields
  • — rows + detail link =61 x2; → PaymentDetailAction (detail.do?paymentId=61); → PaymentRemittanceAction (remittance.do?claimId=)
  • — one payment
  • — rows, count, total
  • — HTTP 200, status null

Actions

  • — every *.do
  • — /payment/issue.do; → SettlementDAO.findByClaim (1); → nextId("PAYMENT") (2); → PaymentDAO.insert (3); → issue.jsp (forward); → error.jsp (exception)
  • — /payment/history.do; → PaymentDAO.findByClaim (read); → history.jsp (forward)
  • — /payment/detail.do; → PaymentDAO.findById (read); → detail.jsp (forward); → error.jsp (exception)
  • — /payment/remittance.do; → PaymentDAO.findByClaim (read); → PaymentDAO.totalIssued (read); → remittance.jsp (forward)

SQL

  • — newest settlement by id; → SETTLEMENT (select)
  • — max(payment_id)+1, DriverManager; → PAYMENT (select max)
  • — 9-column insert; → PAYMENT (insert); → CLAIM (FK)
  • — where claim_id = ? order by id; → PAYMENT (select)
  • — where payment_id = ?; → PAYMENT (select)
  • — coalesce(sum(amount),0); → PAYMENT (sum)

Tables

  • — read only

  • — foreign key only
